# شیفت‌یار

برنامه‌ریز شیفت پرسنل درمانی با تقویم شمسی. سرور Node + SQLite با ورود کاربران و سه نقش، و یک رابط وب فارسی (راست‌به‌چپ، تم روشن و تیره).

## امکانات
- شیفت‌های M / A / N و ترکیبی‌های MA / AN / NM / MN. ساعت هر شیفت از **اجتماع بازه‌ها** حساب می‌شود (هم‌پوشانی ۳۰ دقیقه‌ای فقط یک‌بار). شیفت سفارشی هم قابل تعریف است.
- پرسنل با نوع قرارداد (شرکتی، تبصره ۴، رسمی) و بخش‌های نامحدود با رنگ مخصوص.
- تقویم شمسی ماهانه، رنگ‌آمیزی شیفت با کشیدن، مرخصی (استحقاقی/بدون حقوق)، استعلاجی، استراحت، غیبت، کپی الگو، بازگردانی.
- موظفی ماهانه = (روزهای ماه − جمعه‌ها − تعطیلات رسمی) × ۷:۲۰
- تعطیلی از ۰۰:۰۰ تا ۲۴:۰۰؛ ضریب ۱.۴ برای شرکتی و تبصره ۴ (شیفتِ عبورکننده از نیمه‌شب بین دو روز تقسیم می‌شود)
- اضافه‌کار/کسر کار، هشدار حداقل فاصلهٔ بین شیفت‌ها، گزارش بازه‌ای، خروجی CSV، گزارش تغییرات با نام کاربر.
- **ورود با کد پرسنلی + گذرواژه** و سه نقش:

| نقش | چه می‌بیند | چه می‌تواند بکند |
|---|---|---|
| مدیر سیستم | همه چیز | همه کار؛ پرسنل، بخش‌ها، شیفت‌ها، تعطیلات، تنظیمات، حساب‌ها، لاگ |
| مدیر بخش | پرسنل بخش‌های خودش (و خودش) | ویرایش برنامهٔ همان بخش‌ها، گزارش |
| پرسنل | فقط برنامه و گزارش خودش | فقط مشاهده، تغییر گذرواژه |

## اجرا
نیاز: Node 22.13 یا بالاتر. هیچ بستهٔ npm لازم نیست (SQLite داخلی Node استفاده می‌شود).

```bash
npm start                  # http://127.0.0.1:3000
```
اولین اجرا یک حساب مدیر (`admin`) می‌سازد و گذرواژهٔ موقتش را **یک‌بار** در خروجی چاپ می‌کند؛ در اولین ورود باید عوض شود. برای تعیین دستی:
`ADMIN_CODE=admin ADMIN_PASSWORD='گذرواژه‌ی-قوی' npm start`

### متغیرهای محیطی
| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` / `HOST` | `3000` / `127.0.0.1` | آدرس شنود |
| `DB_PATH` | `data/shiftyar.db` | مسیر فایل پایگاه‌داده |
| `ADMIN_CODE` / `ADMIN_PASSWORD` | `admin` / تصادفی | فقط در اولین اجرا (وقتی هیچ کاربری نیست) |
| `COOKIE_SECURE` | خاموش | پشت HTTPS روی `1` بگذارید |
| `TRUST_PROXY` | خاموش | پشت پروکسی معکوس روی `1` بگذارید (برای IP واقعی در محدودیت ورود) |

### Docker
```bash
docker compose up -d --build
docker compose logs shiftyar | head      # گذرواژهٔ موقت مدیر
```
پورت فقط روی `127.0.0.1` باز می‌شود. برای دسترسی از بیرون یک پروکسی با HTTPS جلوی آن بگذارید (نمونه: `Caddyfile.example`) و در `docker-compose.yml` مقدارهای `COOKIE_SECURE` و `TRUST_PROXY` را فعال نگه دارید. بدون HTTPS گذرواژه‌ها در شبکه بدون رمز می‌روند.
> توجه: Dockerfile در محیط توسعهٔ این پروژه ساخته نشد (daemon در دسترس نبود). چیدمان فایل‌ها با اجرای مستقیم Node بررسی شده، ولی اولین `docker compose build` را خودتان امتحان کنید.

### پشتیبان‌گیری
فایل پایگاه‌داده را وقتی سرور روشن است کپی نکنید. از اسکریپت داخلی استفاده کنید (نسخهٔ سازگار می‌سازد و ۳۰ نسخهٔ آخر را نگه می‌دارد):
```bash
./scripts/backup.sh data/shiftyar.db data/backups
docker compose exec shiftyar node scripts/backup.js /data/shiftyar.db /data/backups
```
آن را با cron روزانه اجرا کنید و نسخه‌ها را جایی خارج از همین سرور نگه دارید.

## امنیت (آنچه پیاده شده)
- گذرواژه‌ها با scrypt و نمک تصادفی ذخیره می‌شوند؛ نشست‌ها با توکن تصادفی در کوکی `HttpOnly` + `SameSite=Strict` (و `Secure` پشت HTTPS)؛ فقط هش توکن در پایگاه‌داده است.
- حداکثر ۵ تلاش ناموفق برای هر کد در ۱۵ دقیقه (و سقف برای هر IP)؛ پیام خطای ورود برای کد ناموجود و گذرواژهٔ غلط یکسان است.
- هر درخواست تغییردهنده هدر `X-Requested-With`، `Origin` هم‌منبع و `Content-Type: application/json` می‌خواهد (دفاع در برابر CSRF).
- مجوزها در **سرور** اعمال می‌شود، نه فقط در رابط: پرسنل فقط داده و برنامهٔ خودش را از API می‌گیرد؛ مدیر بخش فقط در بخش‌های خودش می‌نویسد؛ بازنشانی/غیرفعال‌سازی حساب نشست‌های آن را می‌بندد؛ آخرین مدیر فعال قابل حذف نیست.
- هدرهای `Content-Security-Policy` (فقط منبع همین سرور)، `X-Frame-Options: DENY`، `nosniff`. فونت‌ها خودمیزبان‌اند (فهرست مجوزها: `web/fonts/LICENSES.txt`).

### محدودیت‌های شناخته‌شده
- محدودیت تعداد تلاش ورود در حافظهٔ سرور است و با راه‌اندازی دوباره صفر می‌شود؛ برای یک سرور تکی کافی است.
- هنوز ورود دومرحله‌ای، بازیابی گذرواژه با پیامک/ایمیل و درخواست مرخصی/جابه‌جایی شیفت وجود ندارد (بخش «ایده‌های بعدی»).
- هم‌زمانی: ویرایش‌های همزمان روی خانه‌های مختلف هر دو می‌مانند؛ اگر دو نفر یک خانه را همزمان عوض کنند آخرین ثبت می‌ماند. ویرایش پیکربندی (پرسنل، شیفت‌ها…) فقط توسط مدیر سیستم است و با شمارهٔ نسخه از رونویسی ناخواسته جلوگیری می‌شود.
- تعطیلات قمری هر سال را باید دستی اضافه کرد.

## ساختار پروژه
| مسیر | کار |
|---|---|
| `web/core.js` | محاسبات خالص (تقویم جلالی، شیفت‌ها، تعطیلات، موظفی، اضافه‌کار)؛ هم در مرورگر هم در Node |
| `web/ui.js`, `web/style.css`, `web/index.html` | رابط کاربری |
| `server/app.js` | API و فایل‌های ایستا؛ `server/db.js` پایگاه‌داده؛ `server/auth.js` گذرواژه و نشست |
| `test/` | تست‌ها |
| `scripts/` | پشتیبان‌گیری |
| `build.py` | ساخت نسخهٔ تک‌فایل `shiftyar.html` (برای باز کردن مستقیم یا انتشار به‌صورت صفحهٔ مستقل؛ در آن حالت داده‌ها در `localStorage` مرورگر می‌ماند) |
| `sample/`, `gen-sample.js` | داده‌های نمونه |

## API (خلاصه)
`POST /api/login` · `POST /api/logout` · `GET /api/session` · `POST /api/password` · `GET|PUT /api/config` · `GET /api/assign?from=&to=` (شمارهٔ روز ژولیانی) · `POST /api/assign` · `GET /api/log` · `GET|POST /api/users` · `PATCH|DELETE /api/users/:id` · `POST /api/users/:id/reset` · `POST /api/users/provision`

## فرض‌های محاسبه
جمعه تعطیل رسمی است؛ مرخصی استحقاقی و استعلاجی در روز کاری ۷:۲۰ اعتبار می‌گیرند و در تعطیل اعتبار ندارند؛ شرکتی و تبصره ۴ فرمول یکسان دارند. همه در «تنظیمات» قابل تغییرند.
